## A. Prove-me-wrong items (attack the thesis itself)

A1. **The wv=0.8 MRR gain may be qa_gen overfit.** qa_gen pairs were
    generated by an LLM from the same notes the ranker indexes — the eval
    measures surface-form memorization as much as ranking. The held-out
    audit pairs are saturated (1.0 for both weights, no discrimination).
    Kill test: build a hard pair set (paraphrase + multi-hop questions,
    human-written, not LLM-generated from targets) and re-measure 0.7 vs
    0.8. If the gain vanishes, the promotion was noise-fitting and gets
    reverted.
A2. **d1 wobble ±0.2 on identical input means nothing is "proven" through
    it.** Every chooser decision — and therefore every gate-week statistic —
    inherits classifier noise. The promotion gate can promote on a lucky
    streak. Kill test: re-run the same 27-query sim daily during gate week;
    if per-day verdicts flip on >20% of rows, the gate needs repeat-sampling
    (min-of-N d1 calls) before any promotion can be trusted.
A3. **The gate is circular.** Crystals are judged on traffic the system
    itself induced (injections shape what the model does, which shapes the
    evidence). A frozen gate over self-induced data is not independent
    selection. Mitigation to build: an untouched control split (Telegram
    traffic with the plugin off on alternating days) — if off-day correction
    rates match on-day rates, the crystals add nothing.
A4. **The 43x token saving conflates "not in context" with "not read."**
    The injection is PATHS; the model then reads the full winning note
    anyway (the 5,167 tokens still get consumed — once, by retrieval, not
    re-prefilled). The honest metric is total tokens-per-answer including
    the follow-up read, not injected tokens vs file size. Measure it before
    quoting 43x anywhere public.
A5. **"Total correctness" isn't total.** The exhaustive gate covers a=0,
    b∈0..8191. Negatives are unproven (Python bit-ops on negative b are
    two's-complement; genomes likely fail them). The domain of "total" is
    always a chosen domain — every proof claim must STATE its domain or it
    is marketing.
A6. **The GA has discovered nothing.** Its one champion is the seed
    structure itself (double-and-add was a founder). Re-deriving prior art
    in a tiny space is a sanity check, not a result. Kill test: a run with
    NO informed seed finding a distinct champion (e.g. a hybrid chunk/bit
    genome beating both) — until then, the dreaming station has never
    produced a novel artifact.
A7. **The plugin is scaffolding, so all plugin claims are soft.** The model
    can ignore any injection; "crystal fires" means "a hint arrived." The
    architecture's hard claims wait on stage 2, which does not exist.
    Every plugin number must carry this caveat or it is overselling.
A8. **Task-direction compass is unevaluated guesswork** — keyword family
    matching and a static scaffold injected per turn. It may cost tokens
    and add nothing (models already track threads). Needs its own
    consumed/deviation gate or it gets deleted, not defended.
A9. **The chooser's ~1.2s per non-junk turn may be pure overhead.** Two
    live injections in a day of probes is not evidence of value. If gate
    week ends with consumed-rate near zero on real traffic, the honest
    verdict is the plugin is an interesting instrument and a bad router.

## A-verdicts (2026-11-16, adversarial pass - incrementally proven/disproven)

- A1 DISPROVED + REVERTED: fusion 0.8 gain did not transfer to the hard pair
  set (0.7 wins 0.813 vs 0.750 MRR). qa_gen is a biased eval. Held-out
  second gate now mandatory. (Also: audit qa.json is saturated - cannot
  discriminate anything.)
- A2 DISPROVED (my own worry): d1 is deterministic run-to-run on identical
  requests (0 choice flips, 0 >0.1 conf drift across 27 rows x rules). The
  earlier '+-0.2 wobble' was cross-config: prompt/label CHANGES move
  verdicts, not noise. Consequence: prompts are part of the gate - they get
  frozen and tuned only in the sim, like any other gate constant.
- A5 CONFIRMED: the champion genome fails 60/123 negative-domain inputs
  while passing the 'exhaustive' gate - because the gate's domain (b>=0) was
  chosen to exclude negatives. Every proof must STATE its domain; a proof
  silent about its domain is marketing. Stage-2 law.
- A6 CONFIRMED, deepest finding: pure-random founders -> NO champion in 8
  generations. The proof gate is BINARY (byte-identical or dead) so there is
  no fitness gradient to climb; structural mutation cannot walk a cliff.
  'No gradients, prove once' collides with search needing gradients.
  Dreaming therefore needs either informed seeds (prior art - what worked
  today) or a graded intermediate signal for SURVIVAL while promotion stays
  proof-gated. This tension is a stage-2 design problem, not a bug.

## A4 verdict (2026-11-16): RESOLVED - 43x retracted, honest metric adopted

tokens-per-answer (haystack): 113 inject + E[read] 2,652 = 2,765 tok
(median read 993). Honest compression vs naive full-note re-read: ~1.9x
(median 4.7x), not 43x. The old ratio compared the injection against the
largest sampled winning file. Real saving = avoided SEARCH (wrong reads,
re-derivation, user questions), which is unbounded and was never the
denominator. Committed in haystack 1c095ce; token_metrics.py carries the
correction. A4 closed.

## E. Query-formation pass (Diogo, 2026-11-16 - P3 pass, P2 prototype possible)

'go for it' was not the best way to say 'keep working on task X'. The
architecture needs a QUERY-FORMATION PASS: before any callee (haystack, d1,
any LLM), form the input that maximizes that callee's measured performance.

- In-repo evidence it matters: (1) d1 verdicts flip on prompt/label wording
  (A2: 'research loop' vs 'needs web research' flipped 0.87-no ->
  0.91-yes - the hand prompt-tuning in the sim IS this pass, done manually);
  (2) haystack normalize_query (filler stripping) is a frozen hand-written
  rewrite operator; (3) A1: query style (nickname vs literal) is where
  retrieval fails.
- Genome: chain of rewrite operators (strip filler, synonym expansion,
  PT<->EN normalization, label rephrasing, sub-query decomposition,
  constraint add). Mutation = structural operators on the chain (GA law
  holds).
- Fitness axis per callee: Recall/MRR (haystack), TP/FP discriminative
  power (d1 sim). Selection: existing gates.
- BOUNDARY (do not merge layers): reformatting is NOT intent resolution.
  'go for it' -> 'continue the router task' needs session STATE, not
  rephrasing. The pass consumes the task direction (the compass) as input;
  state supplies intent, the pass supplies form. Two crystals.
- P3 form: the rewriter itself must be a crystallized operator chain
  (no-LLM law) - genome above.
- P2 prototype (buildable now): rewrite-operator genome swept against the
  haystack evals with the hard-pairs held-out gate (A1 discipline). First
  measured numbers would be the pass's proof of concept.
