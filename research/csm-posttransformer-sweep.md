# CSM Prior-Art Sweep — Post-Transformer Cognitive Architectures

Scope: seven non-transformer-native families + the strongest counterargument. Per family: mechanism, why it lost/stalled vs transformers, the stealable piece, and whether its artifacts are deterministic/checkable.

---

## 1. Classical cognitive architectures

### ACT-R (Anderson & Lebiere 1998; Anderson et al., "An Integrated Theory of the Mind", Psych. Review 2004)
- **Mechanism.** A set of independent modules (declarative memory, procedural rule system, goal, perceptual-motor) communicating through *buffers*. Declarative memory is a set of chunks with activation values (base-level + spreading activation + noise); the procedural module fires ONE production per cycle (50 ms), selecting the rule with highest utility (learned expected reward + noise → the single stochastic point in an otherwise symbolic system). **Chunking** (Anderson et al., "Human symbol manipulation within an integrated cognitive architecture", Psych Review 2012): on successful problem solving, the trace of subgoal steps is compiled into ONE new chunk/rule, so N-step procedures collapse into O(1) retrievals — literally "compile experience into rules on success".
- **Why it lost.** Not falsified as cognition — failed as engineering: hand-authored production systems scale poorly; each new domain needs thousands of hand-written rules (e.g. the full-length Algebra/FQA tutors took person-years per domain, rule counts in the thousands). No path to automatic language grounding; activation math over manually curated chunks can't absorb the open world. Meanwhile neural nets got scale-for-free; ACT-R's biggest empirical claims (ideal rational adaptation, module latencies) matched RT data, not internet-scale task performance.
- **Steal for CSM.** (a) **Chunking ≈ crystallization**: ACT-R already runs your compile-on-success loop — success trace → new provable rule replacing the trace. CSM's crystallization is chunking with a Lean/verifier gate replacing utility statistics: compile only what verifies. This is a direct prior art you can cite and differentiate: ACT-R compiles *probabilistically* (utility accumulates; noisy compounding rules), CSM compiles *only on verified success*, so the compiled block is replayable/checkable. (b) The **buffer architecture** — serial bottleneck with typed parallel modules feeding it — is exactly a "router + selected link" topology; cite it as cognitive validation that central cognition is link-selection, not continuous prediction.
- **Deterministic/checkable?** Rules/chunks are symbolic and replayable; utility values and stochastic rule selection are not. CSM inherits the symbolic half and drops the statistics.

### Soar (Laird, Rosenbloom & Newell 1986; Laird 2012, "The Soar Cognitive Architecture")
- **Mechanism.** Everything is production rules over a working memory; decision cycle = elaborate → propose operators → pick one. When knowledge is insufficient → **impasse** → subgoal generated → problem-space search → on success, **chunking** compiles the subgoal's resolution into a new production ("chunking on impasse resolution"), so impasses shrink over time.
- **Why it stalled.** Same scaling wall as ACT-R plus known pathologies documented in the literature: chunk degeneracy (chunks over-generalize, firing in contexts where the original reasoning wouldn't hold), the "data learning problem" (2004, Cognitive Systems Research) — Soar/ACT-R learn rules but struggle to learn *new predicates* from experience. Perception/ambiguity always bolted on (SVS later), never core.
- **Steal.** **Impasse as the crystallization trigger.** This is the cleanest mapping for CSM's router: when no proven block matches (impasse), spawn a slower, externally-verifiable solve (e.g. Lean search, superoptimizer-style exhaustive mutation), then crystallize the result as a permanent link. Soar validates "resolve impasse once, never again." Also steal the discipline that ALL knowledge is one uniform representation — for CSM, all links are one artifact type: proven blocks.
- **Deterministic/checkable?** Production firing is deterministic given WM; the chunk over-generalization problem is precisely the non-checkability CSM's verifier gate exists to kill. Good framing: Soar chunking without verification was the failure mode; CSM re-runs Soar's loop with proof certification.

### CLARION (Sun 2002; Sun & Hélie 2016 handbook chapter)
- **Mechanism.** Dual representation: implicit subsymbolic (top-level) vs explicit symbolic (bottom-level) knowledge with bottom-up rule extraction (from implicit nets to explicit rules) and top-down assimilation.
- **Why it stalled.** The "implicit" half is a trained neural net doing the actual heavy lifting — it's a 2002 preview of hybrid LLM+symbolic systems, and inherits the same opacity. No scale.
- **Steal.** **Bottom-up rule extraction with a confidence criterion** (extract a rule when implicit competence is high) is structurally CSM's crystallize-when-verified, but CLARION extracts from gradient internals — uncheckable. CSM's version extracts from *replayable interaction traces*. Cite CLARION as the family whose hybrid direction was right but whose substrate made verification impossible.
- **Deterministic?** No — the extraction criterion is statistical over neural activations.

### Sigma (Rosenbloom, "A Grand Unified Architecture for Artificial Cognition", 2011–2016 line; Rosenbloom et al., Cognitive Systems Research 2016)
- **Mechanism.** Everything (rules, memories, perception, predicates) is a single primitive: **factor graphs over graphical models**. Continuity/softness is a first-class citizen; cognition is message-passing inference.
- **Why it stalled.** Elegant unification, minimal downstream adoption: message-passing inference is expensive, few full systems were built, and it arrived at the same moment transformers ate the field. No killer app ever demonstrated the unification paying off.
- **Steal.** The claim worth keeping *inverted*: Sigma says cognition is inference; CSM's claim is that cognition is *dispatch over proven artifacts*, with inference only inside small, verified kernels. Sigma's "unify everything in one representation" is a design smell CSM should avoid repeating at full strength (it forces soft everywhere, killing checkability).
- **Deterministic?** No — approximate inference throughout.

### OpenCog / AtomSpace (Goertzel et al.; PLN — Probabilistic Logic Networks, arXiv:2005.12535; OpenCog Hyperon/AtomSpace docs 2020–2025)
- **Mechanism.** Weighted typed hypergraph (Atomspace) + uncertain-logic inference (PLN) + pattern mining over the graph; attention (ECAN) as the router.
- **Why it stalled (2026 status).** Twenty+ years of engineering, AGI-adjacent results (OpenPsi, dialogue systems), but never reproduced a language-competence threshold; the probabilistic semantics of PLN links are hand-tuned and the system's competence scales roughly with curation effort — the same wall as ACT-R/Soar. Notably OpenCog's 2020s pivot (Hyperon) still assumes a learned-nets-inside-hypergraph hybrid.
- **Steal.** (a) The **AtomSpace's grounding discipline**: every atom is typed and traceable — a structural prior for CSM's "every concept has provenance." (b) ECAN-style *attention as a deterministic resource scheduler* maps onto CSM's router. (c) The negative lesson: probabilistic link weights + curation = the exact opposite of CSM's hard-gate; PLN's stall is evidence that "mostly-true" inference chains don't compose into language-level competence.
- **Deterministic?** Graph structure yes; PLN truth values no.

### Family verdict
The architectures pre-discovered CSM's *topology* (serial bottleneck, module buffers, chunk-on-success, impasse-triggered deep search) and died on *scale of grounding*, not on the topology. CSM's differentiator must be stated: grounding comes from verified execution traces + deterministic semantics computation, not hand-authored rules or gradient nets.

## 2. Vector Symbolic Architectures / hyperdimensional computing

Key sources: Kanerva, "Hyperdimensional Computing" (IEEE Computer 2009) and "Computing with distributed random representations" (Neurocomputing 2003); Plate, *Holographic Reduced Representation* (2003); surveys arXiv:2111.06077 and arXiv:2112.15424 (Kymn et al., ACM Computing Surveys 2022, Parts I–II); Gayler (2003) on VSAs; recent: Frady et al. 2024 on VSA deep learning hybrids (e.g. arXiv:2406.04705-line work); Hersche et al., "A neuro-vector-symbolic architecture for solving Horton_ms puzzles" (Nature Machine Intelligence 2023, arXiv:2303.00940); Verga/Qualcomm work on VSA-LLM hybrids (2024).

- **Mechanism.** Concepts = high-dim (10,000-ish) random hypervectors, near-orthogonal; composition = **binding** (e.g. circular convolution or elementwise XOR-multiply: role×filler) and **bundling** (superposition: set-of), plus permutation for sequence. Resulting structures are decomposable by unbinding/estimation — *one-shot, no training, deterministic algebra*. Role-filler trees, analogies (A:B :: C:?) via vector arithmetic, sequence memory — all algebra.
- **Deterministic/checkable?** **Yes, fully** — this is the only family where composition itself is exact algebra, invertible (up to bounded noise), and every composite carries its decomposition. Perfect substrate for CSM's "deterministic concept relation."
- **State of the field 2020–2026.** Healthy but niche: surveys report steady applications (robotics perception binding, spiking-neuromorphic computing — VSA is the canonical algorithm layer for Intel Loihi-class chips, e.g. Hersche et al. 2023 solving Raven-style puzzles *zero-shot* with a VSA architecture and no learning), classification tasks, and hybrid neuro-VSA papers. No VSA system does open-domain language.
- **Why it hasn't taken over.** (a) **Binding keeps only quasi-orthogonality**: bundled structures saturate, similarity degrades with depth (the "noisy cleanup" problem — every composite needs a cleanup memory lookup, which reintroduces a memory design per task). (b) **No automatic grounding**: hypervectors are random seedings; deciding *what counts as a role* for natural language is hand-engineering at the scale transformers made obsolete. (c) **Capacity is polynomial in dimension, and composition noise compounds** — fine for puzzles, bad for long derivations. (d) Community is small; compute/thought is not behind it.
- **Steal for CSM.** Use VSA algebra as the **interlingua of the router**: concepts = hypervectors, relation = binding, context injection = bundling. Router decisions become *deterministic algebra over provenance-carrying vectors* (every hypervector can be unbound back to its source spans — that's replayability of the *routing decision itself*, a property no embedding from a transformer has). Use cleanup memory as the canonical-concept index. Accept the saturation problem by keeping derivations short and delegating long ones to proven blocks (exactly CSM's crystallization logic).
- **Verdict: strongest "steal" in the whole sweep.**

## 3. Conceptual spaces (Gärdenfors)

Sources: Gärdenfors, *Conceptual Spaces* (2000) and *The Geometry of Meaning* (2014); Bechberger & Kühnberger on convex-hull concepts and their representations (2017–2021, including the empirical finding that convexity is violated in human categorizations — "A case against convexity in conceptual spaces", Synthese 2017); formalizations via Dominance graphs / Belkacem et al. on measuring relations (Expert Systems 2019).

- **Mechanism.** Meaning lives in low-dim quality domains (color = hue/saturation/brightness, etc.); concepts = **convex regions** with prototypes; similarity = distance within domains; **concept combination** via intersections/union of regions (the "pyramid" representation of intersections across domains).
- **Why it stalled.** The core theoretical object (convex regions in psychologically-grounded dimensions) requires *dimensionized domains*, and getting those dimensions for open-domain semantics is exactly the "feature extraction" problem the deep learning era solved by letting the network pick dimensions. The literature since 2017 mostly spins on (a) learning spaces from data (which then inherits the learned-core objection), and (b) toy domains (color, shape, smell). Composition rules remain debated (intersective adjectives, antonym handling, "pet fish" problem).
- **Deterministic/checkable?** Yes, *once the space is fixed* — similarity, region membership, combination are pure geometry over stated dimensions. The space itself is the uncheckable part unless dimensions have declared provenance.
- **Steal.** (a) **Convex-region concepts as the semantics of CSM's "relatedness"**: two concepts are RELATED iff regions are adjacent/overlapping in a declared domain — a checkable predicate, unlike cosine similarity. (b) **Prototypes as cleanup-memory anchors** bridging the VSA layer. (c) The domain-splitting discipline (per-domain similarity metrics) is the right shape for CSM's "semantics computation": compute per-domain coordinates deterministically, never a fused embedding. (d) The 2017 convexity-objection literature gives you the honest caveat: convexity should be an approximation, not an axiom — cite when the design doc claims region-adjacency = relatedness.

## 4. Knowledge graphs + provenance; semantic parsing to logical forms

- **Mechanism.** Semantic parsing: NL → executable logical form (Zelle & Mooney 1996; Zettlemoyer & Collins, CCG parsing to lambda-calculus, 2005; Berant & Liang, "Semantic Parsing on Freebase from Question-Answer Pairs", EMNLP 2013 — community/question-answer seeded weak supervision). Extraction with provenance: Open IE (Banko et al. 2007) produces triples *with source spans*; knowledge provenance formalized in PROV and in KB construction pipelines (Dong et al. 2014, Freebase/Google Knowledge Vault line).
- **Deterministic/checkable?** The logical form *over a fixed KG* is checkable (execution is deterministic; answer traceable to triples, triples traceable to spans). The parsing step — mapping NL to form — was learned (statistical) in all successful systems, and KG embeddings (TransE, Bordes et al. 2013; RotatE, Sun et al. 2019; surveys arXiv:2211.03536 and arXiv:2410.14733) are **learned** — that's the boundary to flag: embeddings score plausible edges but don't certify them; nothing in TransE-family work is provable.
- **Why it lost/stalled.** KG completeness/coverage: Freebase shut 2015-ish; Wikidata today is the standard but sparse on implicit knowledge; every KG-QA system needed a neural component for NL variance (the parsing step is where determinism failed). KG embeddings peaked pre-2022 and were then swallowed by LLMs that do implicit "soft KG" work with less curation.
- **Steal.** (a) **Span-grounded triples** as the artifact schema of CSM memory: every injected context must carry (triple, source span, extractor version) — replayable/checkable exactly like a Lean proof cites its environment. (b) The semantic-parsing literature's hard lesson — **NL→form is the weakest deterministic link** — belongs in the design doc's "known open problem" section, not hidden. CSM's answer is to restrict routing vocabulary (router selects among *existing* concepts; it does not parse free NL into novel logical forms — the generative step only happens at glue level inside proven blocks, which get verified).
- **Boundary flag.** KG embeddings = learned cores; cite only as the thing CSM replaces, alongside the transformer-native appendix.

## 5. Retrieval-centric LMs that demote the learned core

- **kNN-LM** (Kassner & Schütze, "Negated and Misprimed Probes Pay Off", ACL 2020; Khandelwal et al. 2019 for the original kNN-LM; "You can't pick your neighbors, or can you?", arXiv:2210.15859; "Why do Nearest Neighbor Language Models Work?", Xu et al., ICML 2023 — best mechanistic answer: kNN interpolates *context-similar* next-token distributions, so it works when the target continuation distribution is locally stable).
- **RETRO** (Borgeaud et al., "Improving language models by retrieving from trillions of tokens", ICML 2022, arXiv:2112.04426): frozen BERT-chunk retrieval injected into a smaller LM, achieving GPT-3-level quality with 25× fewer parameters — the strongest published evidence that the *learned core can shrink dramatically* when retrieval is good.
- **NTM/DNC** (Graves et al., arXiv:1410.5401; "Hybrid computing using a neural network with dynamic external memory", Nature 2016, arXiv:1607.00070).
- **Mechanism.** All three push state into an external, explicit store and make the learned part a controller/interpolator.
- **Why it died.** NTM/DNC: the learned controller could be *trained to use memory* only in-distribution; generalization to longer sequences and novel structure was partial (the Nature paper's own graphs show the London-tube generalization failing at graph scale). Attention-with-large-context in transformers (and later long-context models) did the same job with less machinery, so external explicit memory lost on engineering simplicity, not on principle. kNN-LM: interpolation helps marginally and is brittle; it cannot replace the generative core because it can only re-mix observed continuations.
- **Deterministic?** Retrieval step: yes (given a fixed index). Controller and interpolation: no. That's the family's structural ceiling — **external memory that is still consulted by an opaque learned policy**.
- **Steal.** (a) RETRO is the empirical precedent for CSM's claim that competence ≠ parameter count when the store is good; cite the 25× result. (b) The failure mode to explain in the design doc: every member of this family kept the learned core *as the controller*. CSM replaces the controller with a deterministic router over proven links; the honest risk (see §8) is that link-selection *is* a prediction problem and determinism may be too brittle to act as controller.

## 6. Program synthesis & superoptimization as cognition

- **Massalin, "Superoptimizer: A Look at the Smallest Program" (ASPLOS 1987) + 1989 PhD thesis; Massalin & Pu 1989.** Exhaustive search over instruction sequences, verified against semantics, yielding provably shortest kernels — determinism at the *discovery* level (search) and the *artifact* level (proof). Modern scaling: Massalin-style stochastic superoptimization, "Scaling up Superoptimization" (ASPLOS 2016, dl.acm.org/10.1145/2954679.2872387); STOKE ("Stochastic Program Optimization", CACM 2015 / ACM TOPLAS 2016) — MCMC search + verification; **Sketch** (Solar-Lezama et al., ASPLOS 2008; "Sketching Stochastic Programs", PLDI 2015) — program sketches + constraint solving to fill holes, with **counterexamples driving refinement** (CEGIS, CACM 2015 overview). Also Lens (ASPLOS 2016) for superoptimization-driven code synthesis.
- **Mechanism as cognition.** "Thinking" = exhaustive/mutation-based search over candidate procedures with a verifier as the only authority. The artifact is *the procedure*, not a trace of the search — reproducible, replayable, checkable forever.
- **Deterministic/checkable?** The artifact: yes (byte-level, verifiable). The *discovery* process: Massalin yes (exhaustive), STOKE no (stochastic MCMC) — but that's fine; CSM only needs the artifact to be deterministic, discovery may be stochastic as long as the verifier gates it (this is your AlphaProof-style external verifier lineage).
- **Why it stalled as "cognition."** Nobody in AI seriously claimed superoptimization was cognition — it was always scoped to micro-kernels; exhaustive search is exponential and scoped to short loop-free code. As a *cognitive architecture metaphor* it never had advocates. That's an opportunity: CSM is proposing it as cognition, and the sweep should say so explicitly — the idea exists only as engineering folklore.
- **Steal.** (a) **Dreaming = offline exhaustive mutation of proven kernels** is Massalin with the search space widened; cite Massalin for the precedent that search+verify can beat human designers at kernel level. (b) **Sketch/CEGIS: counterexample-driven refinement** — the loop where the verifier's counterexample shapes the next synthesis attempt is exactly a crystallization loop, with 15 years of published technique to mine. (c) The "artifact over trace" principle: a crystallized block should be a verified kernel, never a transcript.

## 7. 2023–2026 attempts at LLM-free / minimal cognitive agents

- **CoALA** ("Cognitive Architectures for Language Agents", Sumers, Yao, Narasimhan, Griffiths, TMLR 2024, arXiv:2309.02427): taxonomizes LLM agents by memory (working/episodic/semantic/procedural), action space (internal/external), and decision-making (planning/reasoning/learning). Its key move is *centralizing* LLM cognition into an architecture-shaped skeleton — i.e., the field already concedes CSM's shape; it just fills the central node with an LLM.
- **NeSyPr** ("Neurosymbolic Proceduralization for Efficient Embodied Reasoning", arXiv:2510.19429, 2025): distills latent chain-of-thought into composable symbolic procedures executed without the LLM at inference — reasoning is moved into deterministic procedure composition, with the LLM as the *compiler* only at training time. Direct precedent for "inference = link-selection over compiled procedures"; CSM extends it by making compilation verifier-gated (NeSyPr's compilation is unverified).
- **WALL-E 2.0** ("World Alignment by NeuroSymbolic Learning improves World Model-based LLM Agents", arXiv:2504.15785, 2025): extracts symbolic world-model rules from embodied interaction, aligns LLM's implicit world model to them, then acts mostly over the symbolic rules; NeurIPS 2025. Precedent for rule-extraction-with-replayable-artifacts, again with an LLM in the loop at extraction time.
- **LLM-free neurosymbolic agents** more broadly (2024–2026): mostly per-domain (embodied navigation, web agents with state machines); nothing yet claiming *open-domain language competence without a learned core* — the niche CSM targets is empty, which is both the opportunity and the warning (§8).
- **Steal.** (a) CoALA's taxonomy: use it as the vocabulary of the design doc (CSM's memories map cleanly: semantic = concept store, episodic = interaction traces, procedural = crystallized blocks — this gives reviewers a familiar frame). (b) NeSyPr gives the one-sentence citation for "proceduralization of reasoning is feasible and improves latency/reliability." (c) WALL-E 2.0 gives "symbolic rules extracted from interaction, then trusted at inference" — with the CSM delta being proof-gating.

## 8. The strongest prior art AGAINST CSM — what the design doc must answer

**The core argument for learned cores is not convenience; it is that most of the cognitive load is a problem determinism provably cannot solve.** Assemble it in three tiers:

1. **Perception is the hard wall.** Every dead architecture in §1 died where perception begins: Soar needed SVS, ACT-R hand-built feature buffers, Sigma had to become soft (factor graphs) to do perception at all, VSAs ground hypervectors by hand-designed encodings (audio/visual feature extraction is *learned* in every real VSA system). "Concept" presupposes recognition, and recognition of real-world signal is the domain where deterministic rules were repeatedly tried (expert systems' vision projects, CYC's hand-curation at ~100 person-years, conceptual spaces' dimensionization problem) and repeatedly lost to learned statistics. If CSM's concept store depends on learned feature extraction anywhere in the pipeline, the "no learned core" claim is already false; if it doesn't, it must say where concepts come from. The honest framing: CSM can be fully deterministic *downstream of perception* and must declare a perception frontier explicitly.

2. **Ambiguity and the frame problem.** Routing = deciding which concept applies — but natural-language tokens are irreducibly polysemous and the applicable concept depends on unbounded context. Deterministic dispatch requires the space of relevant contexts to be closed; it isn't (this is the practical form of the frame problem, the original objection against symbolic AI — McCarthy 1959, and the practical killer of CYC). The kNN-LM/"why retrieval works" analysis (Xu et al. 2023) is a nice wedge: interpolation succeeds precisely when context is locally stable; CSM's router needs a *stability certificate* per route, or it will silently mis-dispatch. Soar's chunk degeneracy is the same failure inside a cognitive architecture: compiled rules fire in contexts where the original reasoning was invalid. CSM's verifier-gated crystallization fixes rule *correctness* but not rule *applicability* — the verifier checks the block against its problem instance, not against the space of future instances the router will hand it. This is the sharpest single technical objection and deserves a dedicated mechanism (e.g. crystallized blocks carrying applicability preconditions that are themselves verified, plus a retreat path back to slow search on precondition violation — which is Soar's impasse loop made sound).

3. **Link-selection is a prediction problem wearing a different hat.** "Training becomes link-selection, not next-token prediction" — but selecting the next link given context is a classification over an enormous action space under ambiguity, i.e. the same statistical problem. The retrieval-centric family (§5) is the empirical warning: every attempt to make the controller deterministic-or-trivial kept an opaque learned controller precisely because deterministic selection couldn't generalize. CSM must show that its routing decisions are (a) *verifiable* after the fact (replay the route, check each block's preconditions, check final artifact — Lean-style), and (b) *recoverable* when wrong (the route failure is itself an impasse that triggers crystallization). If routes are post-hoc checkable and failures are self-healing, determinism's brittleness is contained; if not, CSM is a symbolic system that fails the way §1's architectures failed. That's the design doc's central bet, and the sweep shows the bet has never been run at this point in the design space — NeSyPr (2025) is the nearest neighbor and leaves exactly the verification gap CSM fills.

ICML 2023; Laird 2012 for chunk degeneracy and SVS; the VSA surveys arXiv:2111.06077 / arXiv:2112.15424 for grounding-by-hand; RETRO arXiv:2112.04426 for the parameter-count wedge; CoALA arXiv:2309.02427 for the field's own concession of the architecture shape.
